# 迷宫逃生完整开发解释

> **仓库展示副本**：集中学习主文档位于本机 `项目学习文档/02_迷宫逃生_完整开发解释.md`。本文件用于 GitHub 阅读，并随主文档同步更新。

这是一份持续更新的学习文档，用来解释《迷宫逃生》从主菜单、程序化迷宫、玩家控制、武器战斗到僵尸行为和关卡结算的完整开发过程。

当前正式版仍是 `v1.3.1`，功能分支已经完成 `v1.4.0` 发布候选。v1.4 把武器、HUD、环境主题和敌人感知统一成“地下城探索与生存”体验，并完成默认长刀、栓动狙击枪、配镜与拉栓、手动换弹、双手持械、视觉与听觉感知、目标记忆、有限群体警报、Utility AI、固定地下城环境和局部雾区。

## 一、先用一句话理解游戏

《迷宫逃生》是一款 3D 生存迷宫游戏：

```text
进入开始界面
→ 选择已解锁关卡
→ 默认手持长刀并直接开放入口
→ 从迷宫外进入入口
→ 探索程序化迷宫
→ 对抗普通和精英僵尸
→ 随时切换枪刀并控制噪声风险
→ 应对固定地下城状态、局部雾区和瘴气
→ 找到终点门
→ 解锁下一关
```

项目重点展示：

- 3D 角色控制和第一/第三人称相机；
- 程序化迷宫生成；
- A* 寻路；
- 感知、决策和执行分层的敌人 Utility AI；
- 双武器切换、手动换弹和枪械/近战反馈；
- 对象池；
- 小地图探索；
- 十关数据配置和本地存档；
- 环境机制；
- 自动测试和多平台交付。

## 二、项目总体结构

| 系统 | 主要脚本 | 负责什么 |
|---|---|---|
| 游戏流程 | `GameDirector`、`GameTypes`、`CampaignProgress` | 页面阶段、选关、开始、胜负和存档 |
| 关卡数据 | `LevelDefinition`、`LevelCatalog` | 十关尺寸、种子、敌人和环境参数 |
| 迷宫 | `MazeGenerator`、`MazeLayout`、`MazeWorld` | 生成逻辑网格并构建三维场景 |
| 寻路 | `MazePathfinder` | 在逻辑网格上执行 A* |
| 玩家 | `GameInput`、`PlayerController`、`CameraRig` | 输入、移动、视角、冲刺和角色状态 |
| 战斗 | `WeaponController`、`Health`、`CombatEffects` | 枪械、近战、伤害、装弹和反馈 |
| 敌人 | `NoiseSystem`、`EnemyPerception`、`EnemyDecisionModel`、`EnemyAgent` | 声音传播、视觉听觉、记忆、Utility 决策和行为执行 |
| 环境 | `EnvironmentController`、`MazeWorld`、`SafeLightLayout` | 固定地下城状态、局部雾区、瘴气和安全灯 |
| UI | `GameHud`、`MiniMapHud`、`MobileControls` | 菜单、HUD、小地图和移动端操作 |

总体关系：

```text
GameDirector 管理当前关卡和游戏阶段
├─ MazeWorld 根据 LevelDefinition 构建迷宫
├─ PlayerController 读取 GameInput 并移动
├─ WeaponController 保存双武器弹药并执行枪械或长刀攻击
├─ EnemyPool 生成 EnemyAgent
├─ EnemyPerception 收集视觉、声音和最后已知位置
├─ EnemyDecisionModel 评分后由 EnemyAgent 寻路和执行
├─ EnvironmentController 应用固定环境，MazeWorld 创建局部雾区
└─ GameHud 根据 GameDirector 和玩家状态显示界面
```

## 三、GameDirector 为什么是核心入口

`GameDirector` 管理当前 `GamePhase`：

```text
Title
Guide
LevelSelect
Staging
Playing
Paused
Won
Lost
```

这些阶段比多个互不相关的布尔值更清晰。例如不需要同时维护：

```text
isTitle
isSelectingLevel
isPlaying
isPaused
isDead
```

当前阶段决定：

- 玩家能否移动和攻击；
- 鼠标是否锁定；
- 显示哪个 UI；
- 是否刷怪；
- 是否计算环境伤害；
- 是否可以进入下一关。

## 四、从打开游戏到进入第一关

### 4.1 开始界面

游戏启动后进入 `Title`。HUD 显示开始、图鉴、设置和退出等入口，玩家暂时不能控制角色。

点击开始后：

```text
GameDirector.ShowLevelSelection
→ Phase = LevelSelect
→ GameHud 显示十关选择
```

### 4.2 关卡为什么会锁定

`CampaignProgress` 使用 `PlayerPrefs` 保存已完成关卡和已解锁关卡。

玩家只有完成前一关，才能选择下一关。读取存档后，关卡按钮根据解锁结果设置 `interactable`。

这属于轻量本地存档，适合作品集单机游戏；它不具备云存档、防作弊和多用户功能。

### 4.3 选择关卡

选择关卡后，`GameDirector` 从 `LevelCatalog` 获取对应 `LevelDefinition`，其中包含：

- 关卡编号；
- 迷宫宽高；
- 固定随机种子；
- 敌人数量和生成节奏；
- 固定 `DungeonCondition`；
- 局部雾区数量；
- 是否有瘴气；
- 是否有精英敌人。

随后调用 `MazeWorld.Build(level)` 构建该关卡，并进入 `Staging` 入口准备阶段。

### 4.4 默认长刀并开放入口

`WeaponController.PrepareLoadout()` 在关卡加载时一次性准备栓动狙击枪和长刀，初始化 5 发弹匣与 20 发备用弹药，并默认装备长刀。随后 `ConfirmLoadout()` 立即开放入口并隐藏旧武器选择面板。角色仍位于迷宫外的准备区，穿过入口触发器后才正式进入 `Playing`。

这样把“确认装备”和“开始计时刷怪”分开，玩家可以先观察操作说明、切换武器和确认入口方向。

## 五、十关为什么每关迷宫不同

### 5.1 固定种子

每关使用不同固定种子。固定种子的意义是：

- 不同关卡布局不同；
- 同一关重新打开时可以复现；
- 测试失败时能定位到相同布局；
- 演示和面试时结果相对稳定。

随机不等于每次都必须不同。工程调试更需要可复现。

### 5.2 Growing Tree 算法

`MazeGenerator` 创建二维 `MazeLayout`，每个格子记录四个方向是否连通。

生成过程：

1. 从起点格开始；
2. 维护已经激活的前沿格子列表；
3. 选择一个前沿格；
4. 找一个未访问邻居；
5. 打通当前格和邻居之间的墙；
6. 将邻居加入前沿；
7. 没有未访问邻居时回退。

当前实现以一定概率继续从列表末尾扩展，否则从旧前沿随机选择。连续从末尾扩展容易形成长通道，从旧位置扩展会增加分岔。

### 5.3 候选筛选

项目不会只生成一次就接受，而是根据关卡要求评价候选布局，例如：

- 起点到终点的路线长度；
- 转弯数量；
- 分岔密度；
- 早期是否出现选择；
- 是否存在足够的支路和死路。

因此后期关卡不仅尺寸更大，也可以在结构上更复杂。

## 六、逻辑迷宫如何变成三维场景

`MazeWorld.Build()` 先调用生成器获得逻辑网格，然后遍历所有格子：

- 创建地面；
- 根据格子开放方向决定是否创建墙；
- 创建墙体装饰和支撑；
- 创建入口准备区；
- 创建开始门和入口触发器；
- 创建终点区域和出口触发器；
- 根据关卡生成避难灯；
- 最后进行静态批处理。

`CellToWorld()` 把二维格子坐标转换为三维世界坐标；`WorldToCell()` 做反向转换。

敌人寻路使用格子坐标，角色和画面使用世界坐标，这两个转换函数把逻辑层和表现层连接起来。

## 七、入口和终点为什么使用 Trigger

入口和终点都是触发区域：

```text
PlayerController 进入 Entry Trigger
→ MazeEntryTrigger.OnTriggerEnter
→ GameDirector.BeginRun
```

```text
PlayerController 进入 Exit Trigger
→ MazeExitTrigger.OnTriggerEnter
→ GameDirector.CompleteLevel
```

Trigger 只负责检测进入，不作为实体墙阻挡角色，因此适合关卡入口、出口、拾取物和范围检测。

开始门的碰撞和显示逻辑与入口触发器分开，避免早期出现“看得到入口但进不去”或“从侧面掉出地图”的问题。

## 八、玩家移动和镜头如何工作

### 8.1 GameInput

`GameInput` 统一读取：

- 移动；
- 鼠标视角；
- 攻击；
- 冲刺；
- 装弹；
- 第一/第三人称切换；
- 暂停；
- 移动端按钮状态。

玩家控制器不直接分别判断键盘、鼠标和触屏，而是读取 `GameInput` 整理后的状态。

### 8.2 PlayerController

角色使用 `CharacterController` 移动。主要流程：

```text
读取移动输入
→ 根据相机朝向转换为世界方向
→ 应用走路或冲刺速度
→ CharacterController.Move
→ 更新重力和地面状态
→ 调用 WeaponController
```

相比直接修改 `transform.position`，`CharacterController` 更适合可控的第一/第三人称角色移动和碰撞滑动。

### 8.3 CameraRig

镜头保存水平和垂直旋转角度。鼠标或触摸改变视角，垂直角度被限制，避免镜头完全翻转。

第一人称与第三人称共享玩家位置和战斗逻辑，只改变镜头位置、角色显示和瞄准方式。

按 `Esc` 暂停时释放鼠标，继续游戏时重新锁定，解决鼠标无法退出游戏画面的问题。

## 九、栓动狙击枪如何攻击

狙击枪流程：

```text
单击攻击
→ 检查弹匣、装弹和拉栓状态
→ 从相机中心发射射线确定瞄准点
→ 从枪口向瞄准点再次检查真实遮挡
→ 命中 EnemyAgent 时造成伤害
→ 播放枪口、命中、后坐力和声音反馈
→ 子弹减少
→ 进入 0.85 秒拉栓，完成前不能再次射击或换弹
```

为什么需要两次检测？

第三人称相机不在枪口位置。如果只从相机发射射线，可能出现相机看得到敌人，但枪口前面有墙，子弹仍然穿墙命中的问题。

装弹期间不能射击。弹匣补满后播放完成提示音并显示短暂 READY，让玩家知道脆弱窗口已经结束。按住鼠标右键进入配镜，FOV 从 68 缩小到 24；每次刚开镜的前三秒使用 0.5 倍时间流速，三秒后继续保持配镜但恢复正常速度。

## 十、长刀如何攻击

长刀不是简单检测一个固定圆形范围，而是结合：

- 攻击距离；
- 面向夹角；
- 墙壁遮挡；
- 攻击冷却。

只有位于有效距离和前方角度内、且没有被墙挡住的敌人才受到伤害。

攻击距离经过调整后比早期小刀更长，但仍然要求玩家主动靠近并承担风险。

## 十一、敌人当前如何行动

### 11.1 EnemyPool

对象池按需要创建僵尸，关卡开始时可以预热一定数量。

生成时：

```text
寻找未激活 EnemyAgent
→ 没有则创建
→ EnemyAgent.Spawn
→ 设置目标、世界、位置和精英状态
→ 重置生命、路径、攻击时间和模型
```

死亡后播放动画，等待约 1.1 秒，再停用对象返回池中。

### 11.2 当前 EnemyAgent

正式版当前使用：

```text
Wander
Chase
Attack
Dead
Inactive
```

更新流程：

1. 如果未激活、死亡、没有玩家或不在 Playing 阶段，停止更新；
2. 计算玩家距离；
3. 近距离进入攻击；
4. 32 米内进入追击，否则游荡；
5. 定期调用 `MazeWorld.FindPath()`；
6. 沿路径格子移动；
7. 攻击时再次使用 Linecast 检查遮挡。

这是 v1.3.1 的旧行为基线。它只根据距离发现玩家，隔墙和浓雾不会真正影响“是否发现”，也没有最后已知位置和搜索行为。

### 11.3 v1.4 已实现的感知、决策和执行分层

状态已经扩展为：

```text
Patrol
Investigate
Chase
Search
Attack
Dead
```

`EnemyPerception` 负责收集事实，不负责移动：它检查玩家距离、水平视野角、墙体 Linecast、环境可见度和局部雾区修正，并保存最后已知位置、声音位置、怀疑度和记忆时间。

`NoiseSystem` 是统一的声音事件总线。狙击枪、长刀、冲刺脚步和僵尸警报都只广播“声音发生位置、半径和类型”，不会把玩家实时坐标持续交给敌人。普通僵尸警报半径为 12 米，精英为 16 米，并有 4 秒冷却，避免一个敌人看到玩家后让整张地图瞬间全知。

`EnemyDecisionModel` 接收感知快照和距离等上下文，对攻击、追击、调查、搜索、巡逻分别评分。它是无场景依赖的纯决策层，因此可以在 EditMode 中单独验证。`EnemyAgent` 只执行最高分意图，继续复用原来的程序化迷宫 A*、移动、攻击、动画和对象池。

完整调用链：

```text
玩家开枪 / 挥刀 / 冲刺
→ NoiseSystem.Emit
→ 半径内 EnemyPerception 记录声音位置
→ EnemyDecisionModel.Evaluate 计算候选分数
→ EnemyAgent 切换 Investigate / Search / Chase / Attack
→ MazeWorld.FindPath
→ MazePathfinder.FindPath
→ 沿逻辑网格移动并在需要时攻击
```

## 十二、A* 寻路如何工作

`MazePathfinder` 不直接在三维碰撞体中搜索，而是在已经生成好的 `MazeLayout` 上搜索。

主要集合：

- `open`：还需要检查的格子；
- `closed`：已经处理的格子；
- `parent`：每个格子从哪里到达；
- `cost`：从起点到该格子的实际代价。

评分：

```text
实际代价 g
+ 到终点的曼哈顿距离 h
= 估计总代价 f
```

找到终点后通过 `parent` 反向重建路径，再翻转为从起点到终点的顺序。

复用迷宫逻辑网格的好处是每次生成迷宫后不需要重新烘焙 NavMesh，也容易在 EditMode 中测试路径是否存在。

## 十三、敌人为什么不会直接出现在玩家脸上

关卡导演先选择合法迷宫格，再创建 `SpawnTelegraph` 预警。经过短暂延迟后，从 `EnemyPool` 获取敌人。

预警给予玩家反应时间，也让“敌人突然凭空出现”变成可读的玩法信号。

生成规则需要考虑：

- 与玩家距离；
- 是否在迷宫有效区域；
- 当前敌人上限；
- 普通或精英敌人；
- 当前关卡难度。

## 十四、小地图如何帮助探索

`MazeExploration` 记录玩家已经走过的格子，`MiniMapHud` 根据记录绘制：

- 已探索区域；
- 玩家位置和朝向；
- 必要的入口或状态信息。

小地图不直接显示完整出口路线，因此它减少迷路挫败，但不取消迷宫探索。

## 十五、环境机制如何增加难度

### 浓雾

`RenderSettings` 全局指数雾在短距离迷宫中容易表现为单纯降低清晰度，因此 v1.4 改成按关卡种子生成的局部雾区。雾区避开入口和出口，敌人在雾区内的有效视距乘以 `0.55`，所以表现变化与玩法规则一致。

试玩发现旧版每个雾区只有一层大尺寸 Billboard，并使用规则 Box 发射区域，近看容易暴露方形贴片和边界。收尾版本把每个雾区拆成三层：

- `Ground Mist`：贴近地面、尺寸较大、透明度低，负责形成连续雾带；
- `Drifting Mist`：位于腰部到视线高度，数量较少，通过 Noise 模块缓慢卷动；
- `Suspended Dust`：极少量小尺寸尘点，只提供空间运动参照，不充当主要雾层。

三层共用运行时生成的 `64 x 64` 柔边噪声纹理，粒子从中心到边缘平滑透明，因此不再显示方形边缘。每个雾区最多 `128` 个粒子，低于测试限定的 `140`，兼顾 Android 性能。玩家进入雾区时，HUD 后层雾幕通过 `MoveTowards` 平滑淡入淡出，整体遮罩不透明度也从旧版明显降低，保证准星、墙体和 HUD 仍可读。

面试时可以这样说：

> 我没有用全局雾直接压低整张画面的清晰度，而是把局部雾拆成贴地雾、漂移雾和少量尘埃，并在运行时生成柔边纹理消除方形贴片。逻辑判定仍由 MazeWorld 的雾区半径负责，表现层只读取同一规则；自动测试还限制每个雾区的粒子预算，避免视觉优化破坏移动端性能。

### 昼夜

当前关卡持续时间较短，连续昼夜循环难以形成可理解的策略，太阳和环境光变化反而会让地下迷宫主题不统一。v1.4 已删除局内连续昼夜循环，改为 `Powered / Dim / Emergency / Blackout / Contaminated / Lockdown / DeepCore` 七类固定地下城状态。状态从关卡开始到结束保持稳定，玩家可以据此判断照明、污染和战斗风险。

### 瘴气

玩家离开安全灯范围后持续受到伤害，需要在探索路线和安全范围之间做取舍。

### 安全灯

`SafeLightLayout` 在主路、支路和死路上布局灯柱，不保证灯光方向就是正确出口，避免灯柱变成导航箭头。

### 地下城分区机制

v1.4 已把十关统一解释成逐层深入地下设施，而不是在短时间内经历昼夜变化。关卡中的难度来自空间和系统状态：

- 入口区：照明稳定，用于确认武器切换、换弹和操作；
- 探索区：多分岔、资源点和可选支路，强调小地图与路径记忆；
- 断电区：视野缩短，需要手持灯或恢复局部供电；
- 污染区：保留瘴气和安全灯，但安全灯不固定铺在正确路径上；
- 警戒区：枪声更容易引来附近敌人，长刀更安静但近战风险更高；
- 出口区：提高敌人压力并形成最后一段撤离战斗。

该分区不要求每关都具备全部机制。每关只组合一到两个主要规则，让玩家能看懂失败原因，也便于测试和面试说明。

## 十五点一、v1.4 双武器与 HUD 改造

玩家不再在开局选择武器，而是默认手持长刀、同时携带狙击枪并随时切换：

```text
数字键 1 / 移动端枪械按钮 → 切换狙击枪
数字键 2 / 移动端近战按钮 → 切换长刀
鼠标右键 / 移动端配镜按钮 → 按住配镜
R / 移动端换弹按钮 → 手动换弹
弹匣为空 → 禁止开火并显示空仓提示，不自动换弹
```

这样不同声音才会形成玩家主动选择：狙击枪射程和伤害高，但每枪拉栓、弹药有限且 42 米枪声会暴露位置；长刀风险更高但更安静。取消开局二选一后，`Staging` 阶段只负责入口准备，不再阻塞玩家选择。

HUD 必须跟随当前武器改变，而不是只替换一行文字：

- 狙击枪：显示弹匣、备用弹药、拉栓/换弹进度、专注时间、空仓提示和配镜十字线；
- 长刀：隐藏弹药，显示攻击冷却、有效距离提示和近战准星；
- 切换时显示短暂武器名称与图标反馈；
- 第一人称和第三人称都要同步正确的持枪、持刀和攻击动作；
- 移动端保留独立换弹键，并增加明确的双武器切换控件。

角色视觉使用现有骨骼动画配合运行时支撑手 IK：离武器握把较远的一只手会贴到狙击枪前护木或长刀刀柄；当前武器手持，另一把武器挂在背部。第一人称相机眼位保持在 CharacterController 胶囊内部，仅向前 0.04 米，并把近裁剪面设为 0.03，避免角色贴墙时镜头先于碰撞体穿过墙面。

换弹采用手动触发。换弹期间允许移动和转向，但不能射击；切换到长刀会中断未完成换弹，再切回枪械时弹匣保持原状态。该规则比自动换弹更容易被玩家理解，也能形成“继续躲避、切刀自保还是冒险完成换弹”的决策。

## 十六、生命、胜负和关卡解锁

`Health` 负责当前生命、最大生命、扣血、恢复和死亡事件。

玩家死亡：

```text
Health.Died
→ GameDirector 进入 Lost
→ 停止角色、敌人和环境更新
→ 释放鼠标
→ GameHud 显示失败界面
```

到达终点：

```text
MazeExitTrigger
→ GameDirector.CompleteLevel
→ CampaignProgress.Complete
→ 保存解锁进度
→ 进入 Won
→ 显示下一关或返回选关
```

## 十七、UI、设置和本地化

`GameHud` 使用 partial class 分拆主 HUD、关卡菜单和图鉴代码，避免单文件继续膨胀。

`PortfolioSettings` 使用 `PlayerPrefs` 保存语言和音量设置，`LocalizedLabel` 负责中英文文本刷新。

设置菜单不会把音量滑块清零；关闭声音只改变静音状态，重新开启后恢复原音量。

## 十八、测试为什么分 EditMode 和 PlayMode

### v1.4 EditMode `21/21`

适合验证不需要真实运行场景的纯逻辑：

- 迷宫一定连通；
- 不同种子结果不同；
- 路线长度和复杂度；
- 安全灯布局；
- A* 路径结果。
- Utility AI 在攻击、追击、调查、搜索和巡逻之间的评分边界；
- 十关 `DungeonCondition` 和局部雾区配置。

### v1.4 PlayMode `44/44`

适合验证需要场景和组件生命周期的行为：

- 开始页、选关、默认长刀和入口准备；
- 角色和入口碰撞；
- 狙击枪单发、拉栓、配镜、长刀和装弹；
- 敌人对象池复用；
- 设置保存；
- 胜负和关卡解锁。
- 视野角、墙体遮挡、声音调查和有限警报；
- 对象池回收后清空感知记忆；
- 空弹不自动换弹、备用弹药转移、配镜前三秒减速、背负武器互斥和切刀中断换弹；
- 固定地下城状态和局部雾区回归。
- 左半屏浮动摇杆按下、拖动、松手与输入归零；
- 移动端战斗按钮分区和低分辨率布局边界。

自动测试用于防止版本迭代破坏规则，不能代替真实玩家对难度和手感的判断。

## 十九、完整调用链示例

### 示例一 选择关卡并进入迷宫

```text
开始按钮
→ GameDirector.ShowLevelSelection
→ 选择关卡
→ LevelCatalog 获取 LevelDefinition
→ MazeWorld.Build
→ MazeGenerator 生成 MazeLayout
→ MazeWorld 创建地面、墙、入口、出口和灯
→ 默认长刀并直接开放入口
→ 进入 Entry Trigger
→ GameDirector.BeginRun
```

### 示例二 僵尸听到枪声后调查并追击

```text
WeaponController.FireGun
→ NoiseSystem.Emit(Gunshot, 30 米)
→ EnemyPerception.OnNoise 记录声音位置
→ EnemyDecisionModel 选择 Investigate
→ EnemyAgent 使用 MazeWorld.FindPath 前往声音位置
→ 进入视野角且 Linecast 无墙体遮挡
→ EnemyPerception 更新最后已知位置
→ EnemyDecisionModel 选择 Chase / Attack
→ EnemyAgent 寻路、移动并按攻击节奏造成伤害
```

### 示例三 玩家用栓动狙击枪击杀僵尸

```text
GameInput.AttackPressed
→ PlayerController 调用 WeaponController.Tick
→ 检查当前武器、弹匣、手动装弹和拉栓状态
→ 相机射线确定目标点
→ 枪口射线检查遮挡
→ EnemyAgent.TakeDamage
→ CycleBolt 协程播放机械声、动作和 HUD 进度
→ Health.Died
→ EnemyAgent.OnDied
→ GameDirector.RegisterKill
→ 播放死亡动画并回收到 EnemyPool
```

## 二十、面试时怎样介绍架构

可以先说：

> 项目由 GameDirector 管理标题、选关、准备、战斗和胜负阶段。关卡使用 LevelDefinition 配置，MazeGenerator 生成逻辑网格，MazeWorld 把网格构建成三维场景，敌人与出口寻路复用同一份逻辑网格。玩家输入、相机、武器、敌人和 UI 分成独立组件，高频僵尸使用对象池复用。

然后根据面试官追问深入某一条调用链，不要一开始把所有算法名堆出来。

## 二十一、项目当前不足

- Utility AI 仍是人工配置的可解释规则，不是机器学习模型；
- 备用弹药暂时没有场景拾取补给，耗尽后必须使用长刀；
- 局部雾粒子在不同图形设备上的可见度可能存在差异，因此 HUD 雾幕承担稳定反馈；
- 没有联网、热更新和商业存档；
- 真机测试次数和设备覆盖有限。

这些不足用于界定作品集范围。v1.4 已解决隔墙全知、声音无意义、短局昼夜和武器二选一的问题，但仍需要作者真人试玩决定数值和手感是否达到正式发布标准。

### 移动端 HUD 收尾

右下角原来同时承担武器状态和操作按钮，Android 上容易重叠。现在 `Weapon HUD` 移到左上顶栏下，只显示武器、弹药、拉栓/换弹进度；右侧保留攻击、开镜、装弹、切枪、切刀和视角按钮，冲刺键放在左下偏中。

左侧固定摇杆改成浮动摇杆：透明触区只覆盖屏幕左半边，按下后在触点显示，拖动产生移动，松手或界面禁用时归零并隐藏。右半屏仍负责镜头滑动。测试直接构造指针按下、拖动和松手事件，验证视觉状态与 `GameInput.Move`。
