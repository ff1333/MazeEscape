# v1.4.0 移动端 HUD 与浮动摇杆收尾

日期：2026-10-31

## 问题

Android 试玩截图中，右下角同时放置攻击、开镜、换弹、切枪、切刀、冲刺、视角按钮和武器状态面板，信息层与操作层重叠。左下角还是固定摇杆，与 2D 项目的浮动触控习惯不一致。

## 设计原则

- 状态信息只负责“现在是什么状态”，不重复显示按键教学；
- 操作按钮只负责“现在可以按什么”；
- 移动与转向各占半屏：左半屏移动，右半屏滑动转向；
- 摇杆默认隐藏，按下左半屏后在触点出现，松手立即归零并隐藏；
- 武器操作仍保留独立按钮，避免切枪、装弹和攻击混在一块。

## 修改

1. `Move Touch Area` 覆盖屏幕左半边，透明但可接收触控。
2. `MobileStick` 在按下位置显示 240 像素摇杆，触点靠近边缘时会把摇杆中心限制在可见范围内。
3. 拖动相对首次触点计算方向，松手和组件禁用时都清零 `GameInput.mobileMove`。
4. 右半屏继续由 `MobileLookArea` 处理镜头滑动，不与移动触点争用。
5. 右侧操作区重新排列为攻击、开镜、装弹、狙击枪、长刀、视角；冲刺移到左下偏中位置。
6. `Weapon HUD` 从右下角移动到左上顶栏下方，只显示当前武器、弹药、拉栓/换弹进度和就绪状态。
7. 状态文本不再出现 `[1]`、`[2]`、`R RELOAD` 等桌面按键说明；移动按钮接入中英文 `LocalizedLabel`。
8. 增加 `-fogboundMobileHud` 运行参数，只用于 Windows 自动画面检查，不改变正常桌面包默认界面。

## 面试讲法

> 我把移动端 HUD 分成状态层和操作层。原来右下角既显示弹药和换弹状态，又摆放七个按钮，导致信息层与交互层互相遮挡。重构后武器状态移动到左上方，右侧只保留战斗按钮；左半屏改成默认隐藏的浮动摇杆，右半屏负责转向。摇杆的按下、拖动、松手和禁用都有明确的输入归零路径，并通过 PlayMode 指针事件测试验证，避免暂停或切界面后角色继续移动。
