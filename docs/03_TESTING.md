## EditMode

`MazeCoreTests` 验证：

- 三种规模的迷宫都有起点到终点路径。
- 相同种子产生相同布局。
- 十关参数合法且机制按计划解锁。
- 十关布局指纹互不重复。
- 网格尺寸、候选数量和目标路线逐关提高。
- 实际选出的主路线长度逐关提高。

## PlayMode

`GameFlowTests` 验证：

- 主场景初始化到开始页；点击开始、选择可用关卡后进入选武器阶段。
- 选择手枪后开始门打开。
- 进入游戏和到达出口会产生正确阶段变化。
- 能连续切换到第十关并生成安全灯。
- 第十关对象池按 14 个敌人的上限完成预热。
- 开始游戏后，敌人会经过出生预警再进入活动状态。
- 统一输入层能够驱动 CharacterController，并切换第一/第三人称视角。
- 第七关以后，玩家离开安全灯范围会受到瘴气伤害。
- 装备后能实际穿过入口进入迷宫。
- 砍刀挥击能伤害前方无遮挡的敌人。
- 手枪准心对准敌人时可命中并消耗一发弹药。
- 已装备但尚未进门时可以暂停、恢复到准备阶段，并返回选武器。
- 小地图不会提前暴露终点；走到相邻格后探索数增加，重新开始则恢复到起点。

`v1.0.0` 结果为 `5/5 PASS`；首次试玩修复后的 EditMode 为 `9/9 PASS`，
PlayMode 为 `10/10 PASS`。

## Windows Player 烟测

正式包支持命令行 `-fogboundSmoke`，单独使用会停在开始页。
加 `-fogboundLevels` 查看选关；加 `-fogboundLoadout` 查看武器页；加 `-fogboundGameplay`
才会选武器并进入游戏。`-fogboundFirstPerson -fogboundWalkRoute` 检查第一人称实体路线。
`-fogboundScreenshot` 后接截图绝对路径。烟测使用独立进度键，不会修改正常玩家的通关记录。
日志必须包含 `FOGBOUND_RUNTIME_SMOKE_PASS`，路线测试还需 `FOGBOUND_WALK_PASS`，并检查 C# 异常。

`v1.0.1` 另外对选武器、第三人称、第一人称手枪和第一人称砍刀运行了真实
Windows Development Player 可见窗口烟测，四组均有截图和 PASS 日志。
Windows Release Player 也启动场景、进入第一人称并保存截图，日志包含
`FOGBOUND_RUNTIME_SMOKE_PASS`。WebGL 仅确认本地 HTTP 服务返回 200，尚未完成
浏览器内交互；Android 仅确认 APK 成功构建，尚未完成 v1.0.1 真机试玩。

## 人工测试边界

自动化可以验证规则和流程，但不能替代手感判断。正式发布前仍要人工检查：

- WASD、鼠标、冲刺、攻击、换弹和视角切换。
- 手枪和砍刀各完成至少一次关卡。
- 雾、昼夜、精英、瘴气和安全灯能被看懂。
- Windows、浏览器和 Android 真机输入没有遮挡或失控。

文档不会把尚未执行的人工测试写成 PASS。
