# 面试讲解稿

## 60 秒版本

迷宫逃生是我用 Unity 6 和 C# 做的 3D 生存迷宫游戏。玩家在迷宫外选择
冲锋枪或长刀，可以切换第一和第三人称，在十个逐渐复杂的迷宫中躲避或击杀僵尸，
到达出口通关。核心技术是固定种子的程序化迷宫、复杂度候选筛选、基于同一网格
的 A* 寻路、敌人状态机和对象池。后期关卡叠加雾、昼夜、精英怪以及安全灯机制。
项目有 EditMode 和 PlayMode 自动测试，并构建 Windows、WebGL 和 Android 包。

## 3-5 分钟结构

1. 先说完整玩法闭环，不先念技术名词。
2. 展示十关复杂度表，解释为什么相同种子有利于复测。
3. 解释运行时迷宫为什么选择网格 A*，而没有动态 NavMesh。
4. 解释 AI 状态与路径重算间隔，说明如何控制 CPU 和 GC 压力。
5. 解释对象池预热和静态批处理分别解决什么问题。
6. 说明自动测试负责确定性规则，人工测试负责手感与平台输入。
7. 讲一次真实试玩反馈：准心模式缺少明确退出路径、玩家在迷宫里迷路；修复暂停出口，增加只揭示已走格子的探索地图，并用测试防止提前泄露终点。

## 高频追问

### 怎样保证迷宫一定能走出去？

Growing Tree 生成时，每个新格子都从已经访问的连通区域扩展，因此生成结果是一棵
覆盖所有格子的连通树。完成后仍用 A* 从起点到终点做独立验证。

### 怎样让后面的迷宫更难？

每关先生成多个候选，优先检查路口密度、第一次选择位置及连续无分岔长度，再比较目标主路线距离与转弯等评分。关卡数据规定
递增的网格规模、候选数和目标路线长度，测试要求最终主路线逐关变长。

### 为什么不用 NavMesh？

迷宫运行时生成，网格已经包含所有可通行关系。复用它做 A* 更确定、更容易测试，
也避免移动端运行时烘焙成本。若以后增加任意形状场景或多层空间，我会改用
NavMeshSurface 或分层导航图。

### 做过哪些优化？

墙体和地面生成后做静态批处理；敌人按关卡上限预热复用；AI 不每帧寻路；
攻击使用 Raycast 或 OverlapSphere；自动测试避免把性能修复破坏成规则回归。

### 当前不足是什么？

角色、僵尸、武器和动画来自 Quaternius 的免费 CC0 素材包，不是我原创建模。
本项目集成了素材导入、Legacy Animation 片段切换、武器挂点和对象池复用时的动画重置；
目前没有制作 Animator 混合树、IK 或完整第一人称手臂动画。敌人只在单层网格中寻路，
平衡测试规模还不是大规模玩家测试。构建成功也不等于所有平台已完成实际试玩。

### 关卡进度如何保存？

开始页和选关页属于显式游戏阶段。只有活着到达出口才保存完成记录，下一关随之解锁。
记录保存在 PlayerPrefs，本机重启后仍在，但不跨设备同步。选关函数本身也检查解锁条件，
不能只把按钮设成不可点。读旧存档时只迁移真正的解锁进度，不能把“上次选了哪关”当作通关。

这份讲稿是复习材料。讲述前应能解释相应代码；使用 AI 辅助完成的部分应如实说明，
不要把自动化测试说成本人逐项手测，也不要把第三方素材说成原创。
